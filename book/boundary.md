# Boundary and non-goals

The long-term goal is Thinkwell implemented in idiomatic Rust. Supported user-facing
concepts, behavior, and guarantees require explicit design and human review.

The completed project scaffolding supplies a compilable workspace, an unpublished empty library, a manually
authored Book, human and agent guidance, and basic CI. The library has no product
API. Rust tool selection and the initial directory layout do not settle product
architecture or supported environments.

Lifecycle and delivery integration excludes fluent plans, sessions, tools, skills, schema generation,
agent launching, ACP/MCP protocol handling, conductor behavior, and all other
product functionality. It also excludes a detailed port roadmap, speculative
dependencies, release tooling, security scanners, changelog automation, package
publication, website deployment, repository settings, branch protection, and secrets.

There are no product anchors yet: no sufficiently precise product guarantees have
been reviewed. Define meaningful properties and verification criteria in a later
design assignment rather than inventing anchors for scaffold files. Scaffolding
completion establishes preparation only. The lifecycle is the Porting Phase; the
engine working mode remains prototyping.
